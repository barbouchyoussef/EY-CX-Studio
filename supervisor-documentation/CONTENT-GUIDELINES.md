# Content Guidelines: EY CX Studio

## 1. Content Voice

EY CX Studio content should be clear, professional, concise, and consulting-oriented. The product should help users understand what to do next without overexplaining obvious interface behavior.

## 2. Language Support

- English and French are supported in user-facing modules where implemented.
- Module copy should live in feature-level copy files.
- Technical documentation is written in English.
- Generated reports should respect the selected workflow language.

## 3. Writing Principles

- Use plain language.
- Prefer action verbs.
- Keep labels short.
- Use consulting terms consistently.
- Avoid vague claims without evidence.
- Distinguish facts, computed metrics, and model-generated interpretation.

## 4. Generated Content Rules

- Generated reports must be reviewed before client delivery.
- Numeric claims must come from computed backend data.
- Recommendations should connect to observed evidence.
- If source evidence is thin, recommendations should be cautious.
- Contradictions between sources should be surfaced rather than hidden.

## 5. UI Copy Rules

- Button text should describe the action.
- Error messages should explain what happened and what the user can do.
- Empty states should guide the next step.
- Loading states should identify what is being processed.
- Admin copy should be precise and avoid ambiguity.

## 6. Report Content Rules

- Use clear headings.
- Start with the main insight.
- Support conclusions with evidence.
- Keep recommendations actionable.
- Separate observations from recommendations.
- Avoid unsupported certainty.

## 7. Content Acceptance Criteria

- User-facing copy is understandable without developer context.
- Reports do not invent metrics.
- Bilingual copy is consistent across module flows.
- Error states are actionable.
- Generated deliverables remain consultant-reviewable.
